As of v4.0.0, `tbp-parser` takes a **subcommand** as its first argument:

| Subcommand | Purpose |
| :--------- | :------ |
| [`parse`](#parse) | Parse a TBProfiler results JSON into the Laboratorian, LIMS, Looker, and coverage reports |
| [`build_gene_db`](#build_gene_db) | Build a `--gene_database_yml` file from the `genes.bed` file of the TBProfiler database |
| [`build_lims_fmt`](#build_lims_fmt) | Build a `--lims_report_format_yml` file from a `--gene_database_yml` file |

---

## `parse`

Parses a TBProfiler results JSON into the four output reports.

```bash
tbp-parser parse \
    --input_json /path/to/data/sample.results.json \
    --input_bam /path/to/data/sample.bam \
    --coverage_bed genes.bed \
    --gene_database_yml gene-database.yml \
    --lims_report_format_yml lims-report-format.yml \

```
See [inputs](inputs.md) section for more details.

??? warning "Input Validation"
    By default, `parse` checks that every gene and gene/drug pair referenced by your BED file, LIMS report format, and results JSON exists in the gene database before it does any work. See [Validation Arguments](inputs.md#validation-arguments) for what is checked and how to turn it off.

## `build_gene_db`

Builds a [gene database YAML file](inputs.md#gene-database-file) from the [`genes.bed`](subcommands.md#where-to-get-a-genesbed) file of a TBProfiler database.

```bash
tbp-parser build_gene_db \
  --db_bed genes.bed \
  --output gene-database.yml
```

| Name | Description | Required |
| :--- | :---------- | :------- |
| `--db_bed` | A BED file containing every gene TBProfiler calls variants against, its locus tag, and the drugs it is associated with | **Yes** |
| `--output` | The path to write the gene database YAML file to | **Yes** |
| `--debug` | Increase output verbosity to debug | No |

The `--db_bed` file uses the same **tab-delimited**, headerless BED format as the coverage BED file. However, the `build_gene_db` command uses the `drugs` (6th) column to build the gene database, while `--coverage_bed` ignores this column. See the [BED file structure](inputs.md#coverage-bed-file) for the column layout and a warning about the `drugs` column.

??? warning "Two behaviors worth knowing about"
    - **Every line must list at least one drug in the sixth column.** `tbp-parser` rejects the file and names the offending lines, rather than skipping them and building a database that is silently missing those genes.
    - **The same locus tag and gene name cannot appear on more than one line.** `tbp-parser` rejects the file with an error rather than merging the lines, so a gene that is split into multiple target regions must be combined into a single line spanning the whole region before building the database.

The generated gene database contains one entry per gene, with the locus tag as the key. Each entry contains the `locus_tag`, `gene_name`, `tier`, `promoter_region`, `drugs`, and `aliases` (if present) associated with that gene. Drugs are de-duplicated and sorted alphabetically. See [Gene Database File](inputs.md#gene-database-file) for the full schema.

??? techdetails "Where `tier` and `promoter_region` come from"

    Both fields originate from the [WHO catalogue of mutations in _Mycobacterium tuberculosis_, 2nd edition (2023)](https://www.who.int/publications/i/item/9789240082410):

    - `tier` — Table 21, "Candidate resistance genes" (p. 89)
    - `promoter_region` — Table 22, "Upstream/promoter regions of candidate resistance genes" (pp. 89-90)

    The same data is published as CSVs in WHO's companion repository, [GTB-tbsequencing/mutation-catalogue-2023](https://github.com/GTB-tbsequencing/mutation-catalogue-2023); `Input data files for Solo algorithms/additional-data/gene_promoters.csv` matches Table 22. Tiers are not published as a flat file there, so Table 21 and the `tier` column of `Final Result Files/WHO-UCN-TB-2023.6-eng_catalogue_master_file.txt` are the only public sources.

## `build_lims_fmt`

Builds a [LIMS report format YAML file](inputs.md#lims-report-format-yaml-file) from a gene database.

```bash
tbp-parser build_lims_fmt \
  --gene_database_yml gene-database.yml \
  --output lims-report-format.yml
```

| Name | Description | Required |
| :--- | :---------- | :------- |
| `--gene_database_yml` | The gene database YAML file to derive the LIMS report format from; either user-provided or generated by `tbp-parser build_gene_db` | **Yes** |
| `--output` | The path to write the LIMS report format YAML file to | **Yes** |
| `--debug` | Increase output verbosity to debug | No |

The format is derived from the **gene database**, not from a BED file: it contains one entry per drug, listing every gene the gene database associates with that drug. A gene with no associated drugs cannot appear in a LIMS report and is left out, with a warning naming each gene that was skipped.

See [LIMS Report Format YAML File](inputs.md#lims-report-format-yaml-file) for the full schema.

Also see [the LIMS report section for more information on this input file, the report, its purpose, and additional customization options.](outputs/lims.md)

## Example Usage

```bash
# 1. build the gene database from the TBProfiler database's genes.bed
tbp-parser build_gene_db \
    --db_bed genes.bed \
    --output gene-database.yml

# 2. build the LIMS report format from that gene database
tbp-parser build_lims_fmt \
    --gene_database_yml gene-database.yml \
    --output lims-report-format.yml

# 3. parse your sample
tbp-parser parse \
    --input_json /path/to/data/tbprofiler_output.json \
    --input_bam /path/to/data/tbprofiler_output.bam \
    --coverage_bed genes.bed \
    --gene_database_yml gene-database.yml \
    --lims_report_format_yml lims-report-format.yml
```

Both YAML files are plain text and can be edited afterwards. The builder subcommands give you a complete starting point rather than a fixed format.

## Where to get a `genes.bed`

Every TBProfiler database includes a `genes.bed` file listing each gene the database calls variants against, its locus tag, and the drugs it is associated with. Which one you need depends on which database you ran TBProfiler with:

- **The default TBProfiler v6.7.0 database** - use [`db/who_v2+/genes.bed`](https://github.com/jodyphelan/TBProfiler/blob/master/db/who_v2%2B/genes.bed) from the TBProfiler repository.
- **A database you updated or created yourself** - follow [the TBProfiler mutation library documentation](https://jodyphelan.github.io/tb-profiler-docs/en/mutation-library/). Whichever route you take, all `tbp-parser` needs is the `genes.bed` file that process generates.
- **Any other supplied database** - the `genes.bed` in your local TBProfiler database directory, or from a branch of [the tbdb repository](https://github.com/jodyphelan/tbdb).

??? warning "The selected `genes.bed` must match to the database used for the sample run"
    The gene database is treated as a faithful representation of the TBProfiler database the variants were called against, so your original TBProfiler run **must** have used the same database you build the gene database from. If it did not, the results JSON will reference genes and gene/drug pairs the gene database does not contain, and [input validation](inputs.md#validation-arguments) will fail the run.
